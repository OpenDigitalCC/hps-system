# Resource monitoring

The IPS asks every paired node, on a fixed interval, how much of its resources
it is using, and writes the answers to syslog. It is for getting a sense of
use (the owner's request of 2026-11-11); it raises no alarms and keeps no history
beyond the log.

## What runs where

- On each node (node-base, node-converged; not the audit image): the ctrl-exec
  `nagios-check` agent script from the pinned `ctrl-exec-plugins` input
  (release tag in `flake.nix`), allowlisted as the node script `nagios-check`
  under profile `node`. It reads no input; its arguments are check names.
  `nix/modules/hps-monitor.nix` installs it, a directory of plugins
  (`check_disk`, `check_load`, `check_swap`, `check_procs` from
  monitoring-plugins, `check_mem` from the plugin repository, and HPS's own
  `check_zpool`) and `/etc/nagios-checks/checks.conf`.
- On the IPS: `bin/hps-monitor`, supervisor program `hps-monitor` running
  `hps-monitor loop`. It calls `scripts/hps-run.sh --json <fqdn> nagios-check --all`
  for each paired node and logs the result.

The targets are the paired nodes only: hosts of the registry that the dispatcher
also lists as agents (names starting `stale-` are ignored). The IPS and the host
it runs on are never checked; there are no local checks.

## Who decides what

| Decided | By | Where |
| --- | --- | --- |
| Which checks run | the IPS, as `--all` (every check the node offers) | `bin/hps-monitor` |
| When | the IPS | cluster key `monitor_interval_seconds` |
| What a check name means: plugin, thresholds, timeout | the node | `/etc/nagios-checks/checks.conf`, generated by `hps-monitor.nix` |

The IPS sends the script name and `--all` and nothing else.

## The node's checks

| Name | Plugin and arguments | Where |
| --- | --- | --- |
| `disk_root` | `check_disk -w 20% -c 10% -p /` | every node |
| `load` | `check_load -r -w 1.5,1.2,1 -c 3,2.5,2` | every node |
| `mem` | `check_mem -w 10 -c 5` | every node |
| `procs` | `check_procs -k -w 1000 -c 2000` (user-space processes; kernel threads left out) | every node |
| `swap` | `check_swap -w 30% -c 10%` | only a node with swap configured |
| `zpool` | `check_zpool` (pool health; DEGRADED is WARNING, FAULTED and worse CRITICAL; capacity as perfdata) | storage nodes |

A netbooted node runs from RAM: `/` is a tmpfs and the store is a squashfs.
`disk_root` therefore measures RAM taken by files written to `/`, and `mem` the
RAM left. `disk` covers the real filesystems, which on these nodes are the
mounted ZFS datasets. Thresholds are the plugin's example values.

## Log lines

Every line goes to syslog (tag `hps`, facility `local0`; OK is `info`, WARNING
`warning`, CRITICAL, UNKNOWN and UNREACHABLE `err`) and, for `hps-monitor run`,
to stdout. OK results are logged too.

```
hps-monitor: host=sch-001.hps.test check=mem state=OK MEM OK - 62% available (9.8 GiB of 15.6 GiB) | available=10522MB available_pct=62%
hps-monitor: host=sch-001.hps.test checks=6 worst=OK duration=1.4
hps-monitor: host=tch-002.hps.test state=UNREACHABLE hps-run exit 4: hps-run: no registered agent for tch-002.hps.test
hps-monitor: tick hosts=3 duration=1.9
```

- `host=<fqdn> check=<name> state=<state> <summary> | <label=value[unit] ...>`:
  one per check; the performance data is omitted when the plugin gave none.
- `host=<fqdn> checks=<n> worst=<state> duration=<s>`: one per host.
- `host=<fqdn> state=UNREACHABLE <reason>`: the node could not be asked (not
  registered, call failed or timed out after 70 s, unreadable reply).
- `tick hosts=<n> duration=<s>`: one per run, so the cadence is visible.
- `tick skipped missed=<k> run=<s>s interval=<n>s`: a run took longer than the
  interval; the ticks it covered are skipped (runs never overlap).
- `disabled (monitor_interval_seconds=0)` and `enabled interval=<n>s`.

Nodes are called in parallel, eight at a time.

## The interval

Cluster key `monitor_interval_seconds`: `0` disables, otherwise 10 to 86400
seconds; default 60 (a value outside the range is logged and 60 used). It is read
before every tick, so a change applies at the next one; while disabled the loop
rechecks the key every 60 seconds. `hps-cluster-config set monitor_interval_seconds 30`.

## Commands

```
hps-monitor run [--host <host>]... [--parallel N]
hps-monitor loop [--max-ticks N]
hps-monitor interval
```
